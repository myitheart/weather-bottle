# 灵动珠 V2.3.1 · Work Outcomes Preview

**单日成果的生成、逐条审核和本地保存已实现。** 在「工作回顾 → 成果」选择一个授权项目和日期，点「生成成果草稿」。可选择今天、昨天或指定日期。工作回顾打开时读取该视图的本机缓存，只有手动生成才读取 Codex 历史。

## 已交付的使用流程

1. **生成。** 把有依据的事项归入新增能力、缺陷修复、工程优化、测试与验证或未完成与待确认。某项实现附带测试时，测试记录跟随该项成果。只有命令、回合或一般过程活动时，可以得到空结果。
2. **核对。** 展开成果查看详细摘要、后续线索、测试输出摘要、补丁和来源等级。选中来源后可打开 Codex 或复制聊天、回合、条目和时间信息。人工确认的来源会显示原适用范围。
3. **审核。** 可确认文字、改标题和摘要、改分类、补下一步、标为待核实或移除。编辑保留原证据，加入的说法标为「人工填写」。业务验证仍在「工作记录」对对应回合填写适用范围。
4. **保存。** 操作成功后自动保存。重新生成时保留人工编辑、确认、待核实和移除状态。旧来源在一次完整读取中缺失时，保留审核内容并提示变化。部分读取会提示可能遗漏，并保留前次已存条目。

## 数据、权限和 AI

| 环节 | 实现 |
| --- | --- |
| 采集和证据 | 复用 V2.3 的 `source_codex`、`service`、`work_items`，普通和归档列表都按精确工作目录匹配。成果只采单项目，按本机自然日过滤证据。用户确认可作为同一回合的关联证据，并带原适用范围。 |
| 规则草稿 | 命令退出码只代表进程结果。「该次测试有通过记录」要求匹配有范围限制的 pytest 或 unittest 命令、退出码为零、捕获到大于零的通过数量。其他测试证据单列为执行记录或会话报告。补丁提供本项目目录内的变更记录及少量文件名；业务结果默认待核实。 |
| 数据模型 | 每份记录按项目、Codex 来源命名空间和日期定位，带修订号、覆盖状态和生成时间。每条成果存稳定 ID、工作事项 ID、分类、标题、摘要、后续线索、原始证据引用、证据和审核状态、生成来源及人工编辑标记。 |
| 保存和清理 | 复用工作回顾 SQLite，从原有结构迁移到 v4。新增 `outcome_days`，审核和重新生成使用事务及修订检查。项目移出回顾范围后不再显示其成果。「工作记录 → 项目设置 → 清除缓存」按项目清除成果与回顾数据。 |
| AI 预览与授权 | 复用 V2.3 的 OpenAI Responses 传输、响应解析和请求限额。「AI 生成」可输入模型名，也可设置 `DYNAMIC_PEARL_OUTCOME_MODEL` 预填。凭据读取 `OPENAI_API_KEY`。先生成规则草稿，再展示本次请求材料和发送地址。用户单独确认后才发送。 |
| 模型输入和结果 | 输入包含匿名别名、分类、有限的证据标签和经筛选的事项主题。完整聊天、绝对路径、会话标识、命令原文、补丁和手写摘要留在本机。模型只拟定候选文字，程序复核成果和证据别名的从属关系，拦截常见的无依据成功结论、重复及跨项目声明。引用无效时保留规则条目并标为待核实。无配置、拒绝、请求失败或异常响应时可继续使用规则草稿。 |

## 真实单日试用

2026 年 11 月 19 日，本机时区 UTC+8，约 18:39 读取一个已授权开发项目。复用本机 Codex App Server 的只读接口，核对 3 个聊天、14 个回合，生成 8 条候选，均归入工程优化。成果附带 69 条补丁引用和 16 条可识别的测试证据。其中 12 条有明确通过记录，4 条只有可核对的执行记录。一次 `unittest` 输出有 64 项通过，另两次分别有 50 和 46 项通过。通过数量按单次执行展示，各次运行可能覆盖同一批测试。

在一条实际成果上比对了补丁的文件数量、记录时间和回合来源。另将三条测试证据的通过数量回查到对应命令条目。使用隔离的 SQLite 确认一条成果、编辑另一条并重开，核对审核状态、修订号及编辑前后完全相同的来源引用。示例只公开活动统计和证据类型。

| 实际源记录 | 生成的候选和核对结果 |
| --- | --- |
| 同回合出现代码补丁和测试运行输出 | 归为工程优化，摘要显示补丁变更和该次测试通过记录。业务结果标为待核实。 |
| 某次测试有命令结束记录，未取得可信的通过数量 | 作为对应成果的测试执行证据，可定位回合，通过结果待核实。 |

## 下一阶段评审重点

- **先评估日清单需要改多少。** 本次样本能从原始活动提取可核对的补丁和测试记录，8 条均为工程类，用户可能仍要把文件级标题改写成早会可用的成果。当前只验证了编辑闭环。建议用几天真实数据记录可直接确认的比例、改写标题或分类的比例、漏掉的事项和审阅耗时。
- **用同日材料比较规则和 AI。** 在本机规则结果有可比基线后，选择获得授权的样本，比较核对耗时和事实错误率。只有经审核的实测可以判断 AI 是否节省整理时间。
- **按日数据可以作为近 7 天回顾的输入。** 先验证同一事项跨天时如何归并、如何呈现相互矛盾的状态，以及周回顾如何保留每日的人工审核与来源。当前交付范围为单日。
