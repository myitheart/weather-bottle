# Dynamic Pearl V2.3 · Phase 0 只读验证

**结论。普通本机聊天可进入 Phase 1 内部原型。** 在两个授权项目的 14 条桌面样本中，公开 App Server 找回全部 14 条。三个真实跨日聊天的范围计数也与桌面连接一致。首个原型应标注采集范围与部分读取，公开发布前仍需非空归档、实际来源回跳和版本兼容验收。

## 验证条件

- 日期为 2026-11-19，Windows 时区为北京时间。Codex Desktop `26.1111.2228.0`，CLI `0.169.0-alpha.11.1`，Python `3.12.10`。
- 项目 1 为灵动珠，项目 2 为用户指定的第二个项目。只对这两个项目的精确根目录读取历史，未扩展到工作树或子目录。
- 用现有桌面连接取普通聊天前两页（40 条）和所有归档元数据（8 条），按授权的精确目录过滤。普通基线为项目 1 的 1 条、项目 2 的 13 条，两个项目都没有归档基线。该基线以桌面工具当时返回的历史为准。
- 使用同版本临时 App Server 的 stdio，`thread/list` 传 `useStateDbOnly:true`。按普通和归档分开扫描，分别对照默认过滤、仅显式来源、仅放宽 provider、两者同时设置。协议只发送初始化和历史读请求。产物只含计数、状态类型、覆盖标记和样本序号。

## 本机结果

| 范围 | 桌面基线命中 | 公开接口发现 | 读取详情与回合 |
| --- | --- | --- | --- |
| 项目 1 · 普通 | 1/1 | 默认 1 条 `vscode`。仅显式来源即发现 1 条 `vscode`、2 条 `exec`。仅放宽 provider 仍为 1 条。两种来源都属于 `paginated`。 | 3 条详情读通，4 个回合。 |
| 项目 2 · 普通 | 13/13 | 四种过滤均读到 100 条 `vscode:paginated`，触及列表页预算。 | 14 条详情读通，97 个回合。 |
| 项目 1、2 · 归档 | 无样本 | 两个精确目录的 `archived:true` 返回空，游标已结束。 | 无可读取样本，归档正例未验。 |

14/14 是被抽取的桌面样本命中率。项目 2 的 100 条是有界读取结果，未覆盖整库。桌面应用的样本可在 App Server 中记为 `vscode`，原型保留原始来源分类。此次单变量对照确认显式来源是项目 1 多出两条 `exec` 的原因，未发现放宽 provider 带来的增量；不能据此推断所有 provider 组合。两项目共 17 条详情的 `projectId` 均为空，原型先用用户选定的 `cwd` 建立本地项目映射。

### 日期、分页及执行证据

- 完整读到 101 个样本回合，起始时间均可读，其中 1 个结束时间为空。项目 2 最长对照聊天有 27 个回合，其 7 页无重复和拒收。两项目共 192 个抽样条目，命令条目中 93 个带结构化退出码，84 个为 0、9 个为非 0，均有非空输出字段。
- 选 3 条真实跨日聊天，用桌面连接翻页对照。合计 53 个回合，双方的回合数、起止时间可用数、覆盖自然日数和三个日期窗口的起止事件计数均相同。日期窗口以北京时间生成。这里只对照了计数与覆盖天数。

| 匿名样本 | 回合数 | 自然日数 | 桌面页数 | 今天、昨天、近 7 天计数 |
| --- | --- | --- | --- | --- |
| A | 27 | 4 | 4 | 三个窗口一致 |
| B | 9 | 2 | 2 | 三个窗口一致 |
| C | 17 | 3 | 3 | 三个窗口一致 |

- 真实抽样中没有单回合跨午夜。匿名夹具验证了秒与毫秒转换、精确午夜前后的半开区间、跨日首尾事件和空时间；还验证了空结果之外的页预算、循环游标、未知方法、内容越界、非法或过大帧与进程提前退出。共 6 项测试。
- 条目按每个聊天最新、最旧的样本回合各取最多 2 页。触及预算时显示 `page_budget`。报告只确认 App Server 能提供退出码和输出存在性，未逐条把命令绑定到测试集、工作树或版本。Phase 1 展示执行事实，测试通过继续待核实。
- 两项目同一探针配置连续运行 10 次。项目 2 每次命中全部 13 条对照，抽样读到相同的 97 个回合，列表和回合均无重复。探针用时中位数约 0.84 秒，按 nearest-rank 取 P95 为 1.39 秒，每次接收约 1.82–1.87 MB。Python 探针的 `tracemalloc` 峰值约 0.57 MB，不含 App Server 进程、原生分配或 GUI。10 次是本机短样本。它支持先设请求预算，未验证晚落盘、并发翻页或 `updatedAt` 提前停止条件。

### 来源定位与未验证项

- 本机 Windows 注册了 `codex` URL 协议，PySide6 `QUrl` 正确解析 `codex://threads/<id>`。本轮未实际导航到普通、CLI 或归档聊天。computer-use 技能限制 ChatGPT 桌面与 Codex 相关界面的自动化，现有 Codex 导航工具按 ID 直接导航，也不能验证 Windows URI 的端到端行为。独立记录此缺口，原型可先输出聊天 ID、回合 ID 和可核对的时间定位。
- `exec` 正例已实测；`cli` 交互式、`appServer` 来源、旧 `legacy` 历史、非默认 provider 正例、工作树和子目录覆盖无对照样本。固定当前版本支持矩阵，能力探测失败时报告缺口。
- 桌面退出重开、读取中新增/归档/撤回、真实压缩或截断、单回合跨午夜正例尚未验证。阶段中未重启桌面或修改现有聊天。上线前需要选定正例与适合重启的验证窗口。

## 复跑

探针位于 [`tools/work_memory_probe.py`](../tools/work_memory_probe.py)，使用 Python 标准库。`--project` 为用户授权的绝对 `cwd`，按传入顺序编号。仅传项目可以检查公开接口；传 `--baseline` 可比较桌面样本。基线 JSON 格式示例为 `[{"project": 1, "threadId": "sample-id", "archived": false}]`。`--baseline -` 从标准输入接收，避免把真实 ID 和项目目录写入仓库。输出不含这些字段，`baseline_index` 对应输入数组的一基序号。

```powershell
.\.venv\Scripts\python.exe -B -m unittest discover -s tools -p test_work_memory_probe.py -v
.\.venv\Scripts\python.exe -B tools/work_memory_probe.py --project $project1 --project $project2 --baseline $localBaseline --thread-samples 14 --page-size 4 --list-pages 25 --turn-pages 25 --measure-python-memory
```

`complete` 表示该扫描读到了游标终点。无样本或页预算均可能使功能覆盖低于期望。未匹配的基线、拒收行、RPC 不支持和页预算写进报告；进程返回 0 表示探针正常退出，验收还需读逐类覆盖字段。生成过程中如需减少数据量，用 `--thread-samples 0` 只取列表，或用 `--item-pages 0` 跳过条目。默认单请求最多 8 秒、总时限 50 秒、单帧 4 MiB、总接收量 32 MiB。

## Phase 1 原型准入范围

1. **纳入**当前版本下用户授权的普通本机 `vscode`、`exec` 聊天。使用显式来源过滤、精确目录、普通和归档分别分页，保留原来源、时间精度和覆盖状态。
2. **先实现**轻量会话和回合读取、今天/昨天/近 7 天按项目排序、取消和错误降级。用轮次/条目去重，缺失的时间单独列出。没有索引一致性实验之前，不用 `updatedAt` 作为增量硬截止。
3. **保持待验收**归档覆盖、旧版本、交互 CLI、实际深链与部署/验收证据。公开投放前重新审核这些支持边界。阶段方案及后续任务见 [V2.3 迭代规划](dynamic-pearl-v2.3-work-memory.md)。
